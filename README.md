# 划词翻译（QuickTranslate）

一个 Windows 划词翻译小工具：**选中英文 → 鼠标旁冒出「翻译」按钮，点一下（或按快捷键）→ 译文跟着鼠标弹出**。

- 后台静默运行，只占一个托盘图标
- **划词即用**：拖选或双击选中文字后，松开鼠标就能看到「翻译」小按钮，不用记快捷键（可关）
- **毛玻璃气泡**：背景是背后画面的实时模糊，短内容自适应宽度，贴边自动翻面
- **多屏跟随鼠标**：气泡出现在鼠标所在的那块屏，副屏在主屏左边也没问题
- **气泡可拖动**：按住气泡挪到顺手的位置，松手后毛玻璃会按新位置重新取样
- 支持**百度翻译**和**任意 AI 大模型**（DeepSeek / 通义 / 智谱 / Kimi / 本地 Ollama）双引擎，随时切换
- AI 模式下**音标 / 释义 / 例句 / 注释分层展示**，例句单独成块，不跟释义糊在一起
- 快捷键可以自己改，改完立即生效，并会自动拦掉会跟系统撞车的组合
- 支持开机自动启动

## 一、最快上手（3 步）

> **还没有 exe？** 去 [Releases](https://github.com/Verpro123/win-quick-translate/releases/latest)
> 下载 `QuickTranslate.exe`，或者按 [第六节](#六自己构建--二次开发) 自己构建。

1. **双击 `QuickTranslate.exe`**，右下角托盘会出现一个蓝色「译」字图标
2. **右键托盘图标 → 设置…**，把翻译引擎的密钥填上（见第二节）
3. 随便找段英文，**选中它并松开鼠标** —— 鼠标旁会冒出「翻译」小按钮；点它，
   或者按 `Ctrl + Alt + T`，译文就出来了

## 二、配置翻译引擎（二选一）

### 方案 A：百度翻译（免费额度大，推荐先用这个）

1. 打开 <https://fanyi-api.baidu.com/>
2. 用百度账号登录，进入「管理控制台」
3. 在「开发者信息」里完成认证（个人认证即可），然后开通**通用文本翻译**服务
4. 记下 **APPID** 和 **密钥** 两串字符
5. 粘贴到本工具的设置窗口里，点「测试连接」确认通了

> 免费额度：未认证 5 万字符/月；个人认证后约 100 万字符/月。
> 个人日常查词完全用不完。

### 方案 B：AI 大模型（翻译质量最好，能带音标、词性和例句）

只要服务商兼容 OpenAI 接口就行。设置窗口里有「快速预设」下拉框，选一个自动填好地址和模型名，你只需要补 API Key。

| 服务商 | 接口地址 | 模型名 | 去哪拿 Key |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` | <https://platform.deepseek.com/> |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 阿里云百炼控制台 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | <https://open.bigmodel.cn/> |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | <https://platform.moonshot.cn/> |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` | 本机跑，不用 Key |

> AI 引擎按 token 计费，查一个单词大概几厘钱。想省钱就用 `glm-4-flash` 这类便宜模型。

## 三、日常使用

| 操作 | 说明 |
|---|---|
| 选中文字后松开鼠标 | 鼠标旁冒出「翻译」小按钮，点一下就能译（可在设置里关掉） |
| `Ctrl + Alt + T` | 翻译当前选中的内容（默认快捷键，可改） |
| 按住气泡拖动 | 把气泡挪到顺手的位置，松手后重新取背景 |
| 单击气泡 | 立刻关掉 |
| 鼠标停在气泡上 | 暂停自动消失，方便慢慢读 |
| 右键托盘 → 百度翻译 / AI 大模型 | 一键切换引擎 |
| 右键托盘 → 设置… | 改快捷键、密钥、气泡外观、停留时间、字号、划词按钮、开机自启 |
| 右键托盘 → 使用方法 | 快速查看本说明 |

**多屏怎么表现**：气泡和「翻译」按钮都跟着鼠标走 —— 鼠标在哪块屏，它们就出现在哪块屏，
贴边时会自动翻到另一侧。副屏挂在主屏左边（坐标为负）也一样。

**改快捷键**：设置窗口里点「点击录制」，然后直接按下你想要的组合键（比如 `Alt + Q`），会自动填进去。

> 💡 **关于快捷键的一点提醒**：`Ctrl + C` / `Ctrl + V` 这类组合系统本身也在用，
> 绑上去之后每次复制、粘贴都会顺带触发翻译。程序**不会阻止你这么设**，
> 只在保存时给一句提醒 —— 用哪个组合是你自己的事。

## 四、常见问题

**Q：划词后没看到「翻译」小按钮？**
1. 设置里看看「选中文字后，在鼠标旁显示『翻译』小按钮」有没有被关掉
2. 在标题栏、滚动条、桌面图标上拖动不算划词，不会弹按钮
3. 用双击选词也可以；按钮只停留 2.5 秒，鼠标移上去会暂停倒计时

**Q：按住气泡拖不动 / 一拖就关了？**
约 4 像素以内会被当成「点击关闭」，多拖一点就是移动。松手后毛玻璃会按新位置重新取样。

**Q：按了快捷键没反应？**
1. 先确认真的选中了文字（划蓝了）
2. 看一眼托盘图标还在不在 —— 不在就是程序被关了
3. 打开设置窗口点「测试连接」，密钥不对会在这里直接报错

**Q：提示「快捷键注册失败」？**
这个组合键被别的软件占用了，去设置里换一个。注册失败时**旧快捷键仍然有效**，不会出现两个都不能用的情况。

**Q：保存快捷键时冒出一句「提醒」？**
那是知情提示，不是拦截 —— **设置照样保存成功**。比如把热键设成 `Ctrl+C` 时，
会提醒你系统自己也在用这个组合，以后每次复制都会弹出翻译。提这一句只是让你心里有数，
**程序不会自动改你的配置**，用哪个组合完全由你决定。

**Q：会不会把我复制的东西弄丢？**
不会。程序取词前会先把剪贴板原内容记下来，取完立刻还回去，你感知不到。
唯一的例外：如果你复制的是**图片或文件**（不是文字），它没法备份，翻译后剪贴板里会留下那段原文。

**Q：取不到词怎么办？**
极少数程序（部分自绘界面的软件、以管理员权限运行的窗口）不允许被模拟复制。
遇到这种，先试试把本工具也用管理员权限运行。

**Q：日志在哪？**
和 exe 同目录的 `quicktranslate.log`，出问题可以翻它。托盘右键「打开配置目录」能直接跳过去。

**Q：配置文件在哪？**
和 exe 同目录的 `config.json`，可以直接用记事本改（改完要重启程序）。

## 六、自己构建 / 二次开发

### 第 0 步：先确认你的 Python 带 tkinter

```bash
python -c "import tkinter; print(tkinter.TkVersion)"
```

- 打印出版本号（例如 `8.6`）→ 没问题，继续往下
- 报 `ModuleNotFoundError: No module named 'tkinter'` → **换一个 Python**

> ⚠️ **这是整个项目最容易卡住的地方，没有之一。**
> 官网安装的 Python 一定带 tkinter，但**精简版发行版**（某些工具自带的运行时、
> 嵌入式打包的 Python）经常把它裁掉。用它跑源码会直接崩，打包出来的 exe 同样起不来 ——
> 而且报错发生在双击 exe 那一刻，很容易误以为是程序写坏了。
> **所以这条命令请第一个跑，别等打包完才发现。**

### 完整流程

```bash
# 1) 进入项目目录
cd win-quick-translate

# 2) 建虚拟环境（可选，但推荐：不动系统里的 Python）
python -m venv .venv
.venv\Scripts\activate          # PowerShell 用 .venv\Scripts\Activate.ps1

# 3) 装依赖
python -m pip install pystray pillow requests keyboard pyinstaller

# 4) 自检：9 项全 OK 再往下走；哪项 FAIL 会直接告诉你原因
python selftest.py

# 5) 打包
python build.py
```

产物：

| 位置 | 说明 |
|---|---|
| `dist\QuickTranslate.exe` | 单文件可执行程序 |
| `QuickTranslate.exe`（项目根目录） | 上面那份的副本，图双击方便 |

体积约 **20 MB**，**内置完整 Python 运行时** —— 拷到别的 Windows 机器上不用装任何东西，双击即用。

### 只想改点东西，不想每次等打包？

直接跑源码，改完存盘、重启程序就生效：

```bash
python main.py
```

**调试阶段用这个最省事**，`build.py` 一次要二三十秒。

### 构建相关的坑

**卡在 "Analyzing dependencies" 很久**
第一次本来就慢（要遍历整棵依赖树）。`build.py` 带了 `--clean`，每次从头构建以保证产物干净；想快可以把那个参数去掉。

**装依赖超时 / SSL 报错**
换国内镜像：
```bash
python -m pip install pystray pillow requests keyboard pyinstaller -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**打出来的 exe 被杀毒软件拦**
PyInstaller 的引导程序常被误报（行为特征和某些恶意软件相似），加信任即可。想彻底避开就直接 `python main.py` 跑源码。

**改完代码准备提交时**
`config.json` 里有你的 API Key，`.gitignore` 已经挡住了它和日志、exe、`dist/`。
**别用 `git add -f` 强行把它加进去。** 提交前扫一眼 `git status`，看到它出现在列表里就要警觉。

## 七、一些实现取舍（给爱刨根问底的人）

**为什么取词用「模拟 Ctrl+C」而不是读 Windows 的选区 API？**
UI Automation 听起来更正统，但 Chrome、VS Code 这类应用的辅助功能接口是**惰性开启**的，
第一次访问要么返回空、要么拖上几百毫秒；还有相当一部分老程序压根不支持。
模拟 Ctrl+C 复刻的是「用户自己按复制」这个行为 —— 只要能复制的地方就能取到词，兼容性最好。

**为什么用剪贴板序号判断而不是往剪贴板塞哨兵值？**
塞哨兵值会污染 Windows 的剪贴板历史（Win+V），看着脏。用 `GetClipboardSequenceNumber`
比较修改序号，既不写脏数据，又能可靠判断「复制到底发生了没有」。

**为什么气泡窗口要加 `WS_EX_NOACTIVATE`？**
不加的话气泡会抢走输入焦点，用户再按快捷键时 `Ctrl+C` 就发给了气泡本身而不是原来的编辑器，必然失败。

**气泡的毛玻璃为什么不用 Windows 的亚克力接口？**
试过了，不行。亚克力（`SetWindowCompositionAttribute`）和 tkinter 做圆角所必需的键控透明
（`-transparentcolor`）抢的是同一套 layered window 属性，实测下来后者会把模糊**完全覆盖**——
窗口还是那个窗口，模糊一点都出不来。
所以改成自己造：气泡弹出前先"拍"一张背后那个位置的屏幕，做高斯模糊、压暗染色、切圆角，
再当卡片底贴上去。代价是每次查词多花几十毫秒抓屏，换来的是**真模糊**，
而且不依赖任何未文档化的系统 API，Windows 10/11 表现一致。

**释义和例句是怎么分开的？**
靠约定格式。系统提示词要求模型按 `音标:` / `释义:` / `例句:` / `注:` 四个固定标记输出，
拿到之后由 `engines.parse_translation()` 逐行解析成结构化字段，气泡再分块渲染。
模型万一没按格式走，解析器会整体退回纯文本显示——**格式跑偏也绝不会白屏**。

**多屏定位为什么不用 tkinter 的 `winfo_screenwidth()`？**
它只认主显示器，副屏会被当成不存在。定位改走 Windows 的 `MonitorFromPoint` /
`GetMonitorInfo`，按鼠标所在那块屏的工作区算坐标（任务栏已经扣掉）。

还有一个坑：tk 的 `wm geometry` 里 `-1182` 表示「距屏幕右边缘 1182」，
**不是负坐标**，所以副屏在主屏左边时根本摆不过去。现在窗口位置统一用
`SetWindowPos` 直接摆，`geometry` 只负责尺寸。

**为什么划词按钮用轮询而不是全局鼠标钩子？**
`WH_MOUSE_LL` 钩子回调一慢，整台机器的鼠标都会跟着发涩；而这里只需要知道
「松开左键时刚才有没有划过一段」，20ms 轮询一次足够，还不会影响别的程序。
拖动标题栏、滚动条会被 `WM_NCHITTEST` 过滤掉，不会误弹按钮。

**拖动后毛玻璃为什么还是清楚的、还不闪？**
拖动松手后用新位置重新拍一张、模糊、染色、切圆角再贴回去。拍的时候用
`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 把气泡临时排除出截屏，
窗口本体一直留在屏幕上 —— 既不会拍到模糊后的自己，也不会出现一隐一现的闪烁。
旧版 Windows 不支持这个标记时才退回「先隐藏、拍完再显示」。
